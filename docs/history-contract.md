# Stored text history

`threads/read` accepts optional `include_turns: true` (default false). This is read-only and never resumes, forks or starts a turn. Before returning any content, the host verifies thread ID and exact workspace cwd.

List items include `{id,cwd,modelProvider,name?,preview?}`; `name` (the actual Codex title) and `preview` (usually the first user message) are trimmed and bounded to 160 Unicode characters each. The Android label prioritizes name. `threads/read` returns metadata by default; with `include_turns:true`, its result is `{thread:{id,cwd,modelProvider},messages:[{id,role,text}],active_turn:boolean}`. Roles are `user` or `assistant`; text comes only from userMessage text content and agentMessage text. Tools, developer/system instructions and upstream error metadata are omitted. Nontext user content is omitted. active_turn reflects upstream `inProgress` status. Existing metadata-only reads and thread resume remain unchanged.

Upstream Codex frames are bounded to 16MiB because stored turns also contain tool output before projection. Downstream response frames support up to 32 MiB, including the journal envelope; commands remain limited to 4 MiB. Results reserve 1 KiB for framing and return `response_too_large` before writing if over budget, so an oversized history cannot terminate the supervisor. The replay journal retains at most 1024 entries or 64 MiB. Paged reads bound the number of turns per request; a single oversized turn can still exceed the transfer budget and must be opened on the computer. Command output uses the separately documented projection limits. Both Android and modex-host must be updated together. Provider credentials remain target-owned. History is sensitive task content intentionally requested by the authenticated user.

## Session model and reasoning

Host status exposes only the allowlisted configured provider/model and optional `effort` from `model_reasoning_effort`. Thread metadata may include `model` and `reasoningEffort`; start/resume results also expose optional top-level `effort`. Missing values remain absent rather than being guessed. Android stores a separate model/effort choice per thread in its encrypted host snapshot, persists it at selection, and gives it precedence over later host defaults or resume responses. New chats resolve host defaults and advertised default effort, while explicit turn overrides leave global Codex configuration unchanged. Forget clears the stored choices; cursor reset preserves them. No prompt is replayed automatically.

## Paged history and Android cache

With `include_turns:true`, callers may supply `limit:1..50` and an optional opaque `cursor`. The host verifies ID/cwd with metadata-only `thread/read`, then calls native `thread/turns/list` with full items in descending order. It reverses each page for chronological display and returns `next_cursor` (empty means end) and `history_revision`. Legacy reads without limit retain their previous behavior. Unsupported Codex pagination is reported as an error, never a silent whole-history fallback.

Android requests 10 turns initially and automatically fetches the next older page when the first visible item approaches the beginning (index 3 or less), after opening at the latest message. Only one older-page request runs at a time. Stable turn/role/item keys preserve the current reading position even if the user keeps scrolling while the page loads. A small progress indicator overlays the timeline without adding a scroll item. Errors pause automatic loading and expose an explicit retry button; retries clear the old error before requesting the same cursor again. Overlapping pages deduplicate by turn/role/item identity and retain newer streamed content. Older pages do not change running-turn state. A changed newest-page fingerprint invalidates older cached pages conservatively.

Up to 10 session snapshots share a 4 MiB serialized cache budget, inside the existing device-local encrypted host snapshot. Oversized snapshots are not cached; they remain viewable in memory. Forget removes this cache. Model/effort preferences remain separately stored per thread.

Manual disconnect, transport failure and process restoration leave the selected chat and displayed messages empty, preserving only the last-thread target and running-turn bookkeeping. Reconnect resumes that target to validate remote ownership before displaying cached content, then refreshes the newest page. An active CLI leaves the landing screen empty with explicit Take over. Delayed resume/history replies cannot reopen a disconnected selection. Cache never grants write ownership; prompts and takeovers are never replayed automatically. Disconnect does not request turn interruption.
